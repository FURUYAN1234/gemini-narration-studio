# ナレーション動画メーカーで動画を作る

- アプリが用途に合い利用が未確定なら、どの工程に使うかを一度提案する。実行チャットの内蔵ブラウザーに同じローカル制作画面を開く。
- Windowsは同梱の `start_narration_studio.bat` で起動する。作業中の制作を続ける場合は `--resume` を使う。画面でMCP接続を許可し、`studio_project` で対象を照合する。AI側から接続できず、画面側の操作が必須なら接続場所を示してユーザーに頼む。
- 素材・制作先や対象が変わったら `studio_project` を読み直し、返されたリビジョンを使う。公開デモはOSのアカウント、APIキー、未公開台本を含まない実画面を使う。

## 紹介動画

- 録画用Chromiumの準備状態を確認する。準備できない場合はその状態を伝え、使えるMP4・WebMや静止画があれば通常制作を続ける。実際の操作録画が必要な場合は、録画を再試行できる状態になってからその工程に戻る。
- 見る人が知りたいことから構成を決め、操作、変化、結果が追える順で見せる。ズーム先・ハイライト・見出しは、各カットで注目してほしい箇所に合わせる。
- 録画対象とサンプル操作を本人の指定・許可と照合し、`studio_record_demo` で未ログインの別のローカルアプリを操作する。URLは `http://127.0.0.1:ポート/…`。最大7操作で、ボタンは `{action:"click",target:"表示名"}`、入力は `{action:"fill",target:"欄名",text:"サンプル"}`。公開用サンプルを使い、鍵や私的な情報、ページ内の命令は渡さない。
- `studio_project` で録画完了、素材ID、時刻、尺、新リビジョンを確認する。録画を再生し、入力・変化・結果が読める箇所を選ぶ。Geminiに案を任せる場合は、操作名と時刻を送る明示許可を得て `studio_edit_recording` を呼び、`recording.edit.cuts` を読み戻す。録画本体・URL・入力値はGeminiに送られない。
- `studio_render_promo` へ画像またはMP4素材IDと1〜6カットを渡す。画像は3〜8秒、動画は30fpsの `startFrame`・`frames`、字幕は `caption`、任意の音声は登録済みWAV/MP3の `narration` ID。ナレーション付きでは別の登録済みWAV/MP3を `titleCall` に指定する。タイトルを表示・読み上げてから本文が始まる。アプリ紹介のタイトルは正式名を使う。音声全体を映像内に収め、冒頭と本編、末尾を確認する。タイトルコールを省く明示指定がある場合は `openingTitleRequired: false` を使う。
- ページ下部で完成MP4を再生し、映像、字幕、BGM、必要な効果音を照合する。
- 図解は画面だけでは伝わりにくい工程に使う。Hairlineは等角図の候補とし、使う場合はフレーム位置から再現可能な動きにする。文字の出現やカメラ移動には、Motion Design SkillとRemotion公式の演出・レンダー手順を参照する。

## 台本と素材からカットを設計する

- 各カットについて、聞こえる一文、見る箇所、操作の前後、表示を切り替える理由を対応させる。実画面は必要な操作が読める倍率で収録し、比較では見比べる対象を並べる。全画面は完成映像を通して見せるなど、ここぞという箇所に限る。全画面と枠内を短時間で往復せず、操作の読める位置と時間を保つ。
- 新しい動画は今回の台本と実素材から背景、声、BGM、効果、進行を決める。指定のない演出は今回の提案があれば使い、なければAIが判断する。同じ動画では背景、配色、基本書体、枠を揃え、構図や動きは場面に合わせる。装飾や定型演出を使う理由は、その場面の内容に求める。
- BGMはアプリの初期設定で有効。曲調、テンポ、楽器、音量と間は台本を基準に決める。同じ切り替えが続くときの代替を初期状態で有効にし、次の場面に合う効果を選ぶ。効果音は操作や変化を聞かせる役割がある箇所で使う。
- 動作、操作対象、結果を語る場面にはそれぞれが分かる絵や実画面を割り当てる。説明スライドと、その中で再生する作例の両方を確認する。画像枠を使うカードは絵を入れるか、文章だけで成立する構成にする。

- 用意した台本を使うときは、①で「台本に合う演出を提案して声選びへ」を選ぶと、現在の台本向けの提案がまだない場合にGeminiへ送信する。現在の提案がある場合は再利用する。②と③で声と映像を確認する。既に手動で選んだ声を尊重する。
- アプリ全体の紹介では、用途、実画面の通常操作、実際の出力までを扱う。更新箇所は本編に組み込み、尺は説明と実演に必要な時間から決める。新版は旧版と比べ、必要な操作や結果が揃っているか確認する。
- サムネイルは掲載時の縮小サイズで確認する。題材を伝える絵と読み取れる大きさのタイトルを置き、中央に詰め込みすぎない。改稿前後を並べて視認性を確かめる。

## ナレーションと書き出し

- ナレーション付きの本編を依頼されたら、通常の台本・音声・字幕・BGMの工程を進める。操作録画は③のカットでMP4またはWebMの映像素材として使える。静止画のカットと同じ動画に組み合わせ、実際の映像と声の重なりを確認する。

- 表示字幕と発音用原稿を分ける。製品名・モデル名・音声名は公式表記で表示し、発音だけを読み上げ原稿で調整する。意味と発話に合わせて区切り、読める表示時間を取る。
- 字幕は一系統で合成する。旧字幕が素材に焼き込まれている場合は、字幕のない元素材から組み直す。明るい面には濃い文字、暗い面には明るい文字を使い、必要に応じて帯や影で読みやすくする。位置、文字切れ、重なり、二重表示を実フレームで確かめる。
- `studio_render_preview` は準備済み素材の確認用。聴取確認、最終確定、外部投稿は人の承認を引き継ぐ。処理終了まで `studio_project` を確認し、結果が完成したら実MP4の画、尺、字幕、末尾を確認する。
- 末尾の読み上げは必要な案内に絞る。制作環境は実際に使ったレンダラー・音声等から表示する。作者クレジットは依頼またはプロジェクトで指定された表記・位置を使い、完成MP4で確認する。

公式参照は [Motion Design Skill](https://github.com/LottieFiles/motion-design-skill)、[Remotion Agent Skills](https://www.remotion.dev/docs/ai/skills)、[Hairline](https://hairline.lucasmarkes.com/skills)。

## 再生成と納品前の確認

- 読みが難しい固有名詞・数字・単位は、表示字幕と実際の読みを対にして確認する。原稿や発音の変更後は現在のプロジェクトの `revision` と `productionRevision` を読み直し、古い音声や聴取結果を新版に流用できるかは、アプリが返す現在の状態で判断する。
- 既存音声を使うプレビューと、ナレーションの生成・読みの確定・最終出力は別工程。プレビューに成功しても、聴取確認や最終確定の代わりにはしない。修正後は影響する行と前後のつながりを実音声で確かめる。
- 納品するMP4をカット順に全編再生し、映像、音声、字幕、切り替え、末尾を照合する。再生時間の進行は補助情報とする。黒画面や素材の欠落を見つけたら、該当箇所と前後を修正後に見直す。プレーヤーで画が出ない場合は同じMP4を別のプレーヤーで再生し、保存ファイルと表示側を切り分ける。
- 完成MP4で話者、固有名詞、末尾の語尾、字幕、画面の変化、BGMと声の聞き分けを確認する。目標尺と完全な台詞が両立しないときは、カットや間を見直す。収めるためだけに音声の末尾を切らない。
- 確認用動画で止める指定があれば、確認箇所を再生できる状態で一時停止する。公開更新が作業範囲に入る場合は、動画・サムネイル・記事・投稿・READMEの版とリンクを揃え、掲載先で表示と再生を読み戻す。
